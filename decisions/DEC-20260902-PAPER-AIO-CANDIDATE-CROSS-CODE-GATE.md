# Require a cross-code scientific gate before any full-data new candidate

Date: 2026-09-02  
Authority: user-approved full-data paper and algorithm-reconstruction plan

## Decision

New route-1 algorithms are dynamic evidence-derived candidates, not additional
names in the old frozen paper lane list. A candidate that passes small25 e200
may proceed toward full data, but it may not reuse the authorization or
protocol identity of the already-running plain checkout. Adding its model
changes the source fingerprint even when the common UNSB initialization is
intended to remain identical.

The repository now requires two separate gates. First, a cross-code GPU gate
on the same host/runtime as the full paper plain must prove exact e0 scientific
cores, exact native 2000-update transitions, exact disabled-candidate identity,
exact candidate resume, and exact repeated evaluation. Second, an evidence
lock binds that result to the source-bound positive small25 e200 receipt,
trajectory, no-plain-collapse guard, derivation card, implementation and source
hashes, and the complete parent plain e200 state.

The evidence lock deliberately records `full_data_authorized=false`. A fresh
authorization tied to the candidate Git commit and candidate protocol
fingerprint is the only object that may start its 1,710,600-update run. This
prevents a new checkout from treating mathematical intent, similar e0 values,
or a copied checkpoint as proof of matched execution.

This decision does not preselect ST-CGR or any other candidate. ST-CGR remains
small25-only until its complete terminal receipt is positive and every new gate
passes. A negative or incomplete trajectory, stale source, runtime mismatch,
or failed identity/resume/evaluation check remains unconditionally blocked.
Paired online control, cross-host deltas and confirmation20 remain forbidden.
